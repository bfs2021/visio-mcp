# W14 File Drops and Clipboard Pictures Implementation Plan

> **Execution gate:** The W14 design is approved. Review this plan before product implementation. It is written for small, independently verified commits on `codex/w14-file-drop`.

**Goal:** Accept user-initiated drops of diagram, Visio and supported picture files, and explicit clipboard picture paste, while preserving document state, existing text and shape paste behavior, and the approved asset pipeline.

**Architecture:** A native Windows gesture creates opaque, bounded, single-use ingress tickets. Internal host handlers consume tickets through the existing document-open and asset-import authorities. The renderer receives only ticket identifiers and safe display metadata. A visible ordered queue handles mixed drops; image imports produce explicit, revision-pinned placement offers. Clipboard image import runs only for an explicit paste outside text editing and uses a native clipboard sequence plus private in-memory-copy marker to preserve ordinary shape paste.

**Tech Stack:** WPF/.NET 10 host, typed internal host bridge, React/TypeScript editor, current diagram/Visio importers, approved `AssetPreparer` library flow, Vitest, Playwright and Windows/native Visio tests. No new dependency or document format change.

**Spec:** [W14 design](../../design/W14-file-drop.md), approved by the user on 2026-10-19.

## Global constraints

- Keep external path admission in native OS gesture handlers. Renderer/MCP callers never mint tickets or submit file paths. No public MCP/live-control discovery of ingress or clipboard internals.
- Tickets are random opaque IDs, window/channel-bound, single-use and expire within five minutes. Bound each gesture to 32 files and pending ticket/bitmap memory. Dismissal, expiry, channel replacement and shutdown release retained resources.
- Admit only `.diagram.json`, `.vsdx`, PNG, JPEG, BMP and SVG. Reuse current file size, image dimension and SVG sanitizer checks. Never enumerate folders or resolve shortcuts, URLs, HTML or generic rich clipboard data.
- Preserve the current Open allowlists, remembered reopen policy, per-window document scope, revision/disk checks, tab limits, duplicate-path activation, untouched-blank reuse and unsaved-change protection. Keep partial success for separate items and report each failure.
- Pictures enter the existing approved library first. Placing is explicit and uses `EditorModel.placeAsset` as one atomic undoable transaction. A stale document/page/revision never retargets the offer to the active tab.
- Preserve internal canvas shape/group copy-paste, text editor paste and W08 Copy as image. Clipboard capture happens only after an explicit paste action outside text-editing controls; there is no background polling.
- Avoid W15 ownership: no associations, Open with, single-instance forwarding or launch-request changes. W15 #37 is currently claimed by Claude and changes shared startup, `MainWindow`, host and IPC code. Before implementation, pull the latest `main`, inspect W15 PR/integration state and coordinate any shared-file overlap in both issues. If W15 is still unmerged, hold overlapping native integration until the owner agrees on a base/merge sequence; do not copy its changes or silently resolve ownership. W13 PR #71 is also in review; start from its integrated head when available or keep this branch explicitly stacked and rebase after it lands.
- Do not edit historical `IMPLEMENTATION_PROGRESS.md`. Preserve existing W12 menu/help and W13 preferences behavior. Small commits; run the standard checks before each push and keep initial failures/retries in evidence.

Ticket records contain normalized path or captured bitmap plus validated kind; renderer-visible notification contains only batch ID, opaque ticket ID, kind and sanitized display name. Add typed internal messages for `host.ingress.available/open/importImage/dismiss` and clipboard descriptor/marker/image import. Keep these out of MCP/live-control discovery.

## Task 4: Approved picture import and explicit placement offer

**Interfaces:** `host.ingress.importImage(ticketId)` consumes an image ticket and calls the same `PrepareFile`/`AssetPreparer` import path as the image library. Renderer offer state references only the returned approved asset identity/thumbnail plus the pinned target. Choices are **Place in [drawing]** or **Keep in library**; canceling the offer leaves an imported asset in the library.

- [ ] Add failing host/editor tests for PNG/JPEG/BMP/SVG, deduplication, import limits and SVG sanitization, Keep in library, offer cancel, one atomic undo, zoom/scroll coordinate conversion, stale tab/page/revision refusal, and library retention after stale/cancelled placement.
- [ ] Implement image import with ticket-path content validation at consumption. Reuse approved import and deduplication; never trust extension/display name. Do not mark the document modified merely by importing to the library.
- [ ] Implement explicit placement offer and revalidate the exact document/session/page/revision/asset at click time. Reuse `placeAsset` transaction and existing sizing/aspect behavior. If stale, keep the asset and require a fresh placement choice.
- [ ] Verify drop-at-point and centre placement, page switching, target close/replacement, and one-step undo in browser and Windows host tests. Commit `feat(w14): offer explicit placement for imported pictures`.

## Task 5: Explicit clipboard picture paste with precedence

**Interfaces:** Host `clipboard.describe`, `markInternalCopy(copyId)` and `importImage(expectedSequence)` are callable only through the existing internal bridge. The private per-window format marks the in-memory element payload with a copy ID and native clipboard sequence; it contains no document data/path. Internal element paste remains local and cross-tab. External bitmap capture/import requires an explicit paste outside editable text and canvas text editing.

- [ ] Add failing unit/Windows/browser tests for internal shape/group copy across tabs, matching marker precedence, a newer external bitmap, W08 Copy as image, sequence change before read, busy clipboard, unsupported external text, textarea/contenteditable/canvas text paste, and no double dispatch.

- [ ] Test the live Windows clipboard with saved/restored user clipboard state in a serialized fixture. Verify an external image never pastes stale shapes and internal copy never imports a duplicate picture. Commit `feat(w14): preserve shape paste and add explicit image paste`.

## Plan self-review

The tasks move from authority and capability boundary to guarded open, native drop, approved image placement, clipboard precedence and integrated acceptance. The design's major safety conditions each have a named test: ticket fabrication/replay/window binding, load allowlists, stale revisions and targets, partial mixed-drop success, SVG sanitation, text-input paste, cross-tab element paste, clipboard sequence races and W08 image-copy compatibility. Integration checks explicitly account for active W15 ownership and the W13 stacked base before shared shell code is touched. The implementation remains within W14's approved scope and does not create a generic file/clipboard API.
