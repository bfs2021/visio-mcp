# R16: branches that join a connector, and hops over crossings

Issue #11. Evidence: `artifacts/r16-junctions/` (`editor-before.png`, `editor-after-move.png`, `visio.png` drawn by Visio itself, `junctions.vsdx`, `junctions-visio-saved.vsdx` as Visio re-saved it, `verification.txt`).

The Lego drawing draws its buses as many single-segment lines with T-junctions where a branch meets a line, and five hand-placed arcs where lines cross. A connector end can now be a **join** on another connector, and a connector can **hop** over the ones it crosses.

## What was added

- **Join.** `Endpoint.join { connectorId, position }`. `position` is a fraction (0 to 1) of the target connector's drawn length from its start, the same measure R13 uses for pins and labels. A joined end has `glue: none`; its `point` is kept on the target's route by the engine, so rendering, routing, bounds and layout inspection treat it as a free end at that place. A joined end is not reported as `UNGLUED_CONNECTOR_END`; one whose target is missing is `DANGLING_CONNECTOR`.
- **Follows.** After every change the engine puts each joined end at its place along the target's route *as drawn* (straight, elbow or curved), in the same undo step as the change that moved it (`commands/joins.ts`, run before the R13 pin settling so a pinned shape follows the route as the branch leaves it). A branch of a branch works: the pass repeats, up to 8 levels. Undo and redo replay stored diffs, so one undo returns the branch and what moved it.
- **Refusals.** A connector cannot join itself, a shape, or a connector that would join it back (directly or through others); a position outside 0 to 1 is refused. Deleting the target releases the end where it stands.
- **Copies.** Duplicate and paste keep a join when the target is copied too (the copy joins the copy) and release it where it lands when it is not. Duplicate page remaps joins.
- **Hops.** `ConnectorElement.hops: none | arc` (absent means none). A hopping connector draws a half-circle arc, 8 pt wide, to the left of its direction of travel where it crosses another connector. Not drawn at a join (the connectors it is joined to, or that join it), near a corner or an end (less than 6 pt), or closer than 10 pt to another hop. Where two hoppers cross, the one on top hops. Not available on a curved route.
- **Operations (MCP).** `createConnector` end takes `join { connector, position? }` (`glue: none`, no point); `set` patches `from`/`to` with the same and `hops`; `createConnector` takes `hops`. `get_document_summary` shows `join` in the ends and `hops` on connectors. DrawScript: `connect ... toJoin=bus toAt=60% hops=arc` (`fromJoin`, `fromAt` likewise); `set LINK toJoin=bus toAt=0.3`, `set LINK hops=arc`.
- **Editor.** Dropping a connector end within 8 screen pixels of another connector's line joins it there (not near the line's own ends, which belong to shapes). The Inspector shows "Hops over crossings", and for each free end a "joins a connector" list; a joined end shows its place as a percentage and a Release button, so it can be done without a pointer.
- **Visio.** Visio cannot glue a connector to a point on another connector. A branch is written as a connector whose end sits on the line, with `AgentJoinFrom`/`AgentJoinTo` user cells holding the join (`join_not_native`, info). On import those cells restore the join; a join to a connector that is gone, or that would loop, is dropped (`join_connector_missing`).
  A free end that Visio drew on the middle of another line is also read as a join (`join_inferred`, info), with no user cells needed: this is how the T-junctions of a drawing made in Visio come in. Only lines whose drawn path is certain count (straight, with waypoints, or an axis-aligned elbow), within 0.75 pt, and not at either end of the line.
  Hops: a hopping connector is written with `ConLineJumpCode 2` (always) and `ConLineJumpStyle 1` (arc); every other connector with `ConLineJumpCode 1` (never), so Visio's page default does not add jumps the editor does not show. Visio only jumps a line when it reroutes it, so the arcs are also written into the geometry (`ArcTo` rows) and appear as drawn; the cells keep them when Visio reroutes. Reading back: `ConLineJumpCode 2` with an arc or default style is `hops: arc`.

## Limitations
- Manual human acceptance (the owner drawing and editing branches and hops by hand in the installed app, and opening the file in Visio) is NOT RUN.
- In Visio a branch is not glued to the line and does not follow it if the line is moved there; reopened in the editor it follows again. Visio draws the arcs only because they are in the geometry; if Visio reroutes a hopping connector it applies its own jump rules (always, arc), which may place them differently.
- The Lego drawing's five hand-placed arc shapes are ordinary shapes and are not turned into hops; only its T-junctions are recovered.
- A hop is a fixed 8 pt wide half circle; there is no size or style choice (Visio has several). Curved connectors do not hop.
- Hops and a branch's follow-up are computed when a change is committed, not live during a mouse drag of an end shape (the same as R13 pins).
- Inferred joins use the drawn ends Visio stored. A line whose path the importer cannot know (a Visio elbow or curve with no waypoints that is not axis-aligned) is not used as a target.
