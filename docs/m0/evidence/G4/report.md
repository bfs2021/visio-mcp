**Result: PASS.** `dotnet test spikes/webview.tests/WebViewProbe.Tests.csproj`: 19 of 19 pass (11 origin cases, 8 behaviour tests), stable over 3 runs.
Windows 11, WebView2 runtime 155.0.4283.60, Microsoft.Web.WebView2 SDK 1.0.4258.31, .NET 10.0.402. The test window is real but placed off-screen (`Left=-10000`); capture and rendering still work.

## Findings to carry forward
1. **`/assets/` is reserved** for content-addressed images, so the Vite build must not emit to `assets/`. The probe sets `build.assetsDir = 'app'`. Before this, the page loaded but its scripts 404'd silently, which looked like a bridge failure.
2. **`ExecuteScriptAsync` does not await promises**; it returns `{}` for an async script. The probe evaluates through the DevTools `Runtime.evaluate` with `awaitPromise`, which works even with DevTools disabled in settings.
3. **Child frames:** registering a `CoreWebView2Frame.WebMessageReceived` handler in `FrameCreated` reliably catches iframe messages, so they never reach the top-level handler. The packaged page posts `editor.ready` on load, so an iframe of it is a realistic hijack attempt, and it is rejected.
4. **SVG-as-image cannot fetch** the host-served URLs, so offscreen export must inline already-approved bytes as `data:` URIs. The page fetches the asset same-origin, verifies the SHA-256 against the URL, then inlines it. This matches the design note about avoiding canvas taint.
5. **Crash handling:** `Page.crash` (DevTools) reproduces a renderer exit; `ProcessFailed` fires and the host settles every pending call. Recovery is `Reload()`, and a fresh `editor.ready` starts a new session.
6. maxGraph contains a direct `eval` (the bundler warns). Nothing in these tests reaches it under a CSP without `unsafe-eval`. Keep `unsafe-eval` out and treat any CSP violation in production as a bug to fix.
7. The bridge correlation ID is generated by the host and mapped to the caller's request ID, so a page cannot answer a request it was not sent.
